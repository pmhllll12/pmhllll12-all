`pmh_flutter_application_1` + `minho`의 auth 게이트웨이에 카카오 로그인을 붙이며
2026-08-03에 겪은 것들. 콘솔 화면에서 원인이 안 보이는 항목만 적는다.

## 이메일은 개인 개발자 앱에서 못 받는다

카카오는 이메일 수집을 **비즈니스 앱**(사업자등록번호 + 심사) 전환 이후로 제한한다.
개인 개발자 앱에서는 콘솔 → 카카오 로그인 → 동의항목 → **개인정보** 섹션의
`카카오계정(이메일)` 이 **"권한없음"** 으로 잠겨 있다.

그래서 모바일 로그인의 `sub`는 이메일이 아니라 **`kakao:{회원번호}`** 다
(`apps/auth/router_mobile.py`). 웹 흐름(`router.py`)은 여전히 이메일을 `sub`로 쓰므로
**같은 사람이 웹/모바일에서 다른 `sub`를 갖는다** — 합치려면 users 테이블에
`kakao_id ↔ email` 매핑이 필요하다.

**Why:** "이메일 동의항목을 추가하면 된다"고 판단해 콘솔을 한참 뒤졌는데, 애초에
개인 앱에는 그 선택지가 없다. 이메일을 사용자 식별자로 설계하면 카카오 로그인은
개인 개발자 단계에서 아예 동작하지 않는다.

## 에러 코드

| 코드 | 실제 원인 |
|---|---|
| `KOE004` "앱 관리자 설정 오류" | **카카오 로그인 활성화(사용 설정)가 OFF.** 앱키·키 해시와 무관하다 |

## 콘솔 UI

메뉴 구조가 자주 바뀌어 URL·경로 안내가 잘 빗나간다. 앱 ID는 주소창
(`/console/app/{앱ID}/...`)에서 확인하고, 페이지 안에서 `Ctrl+F` 로 항목 이름을
찾는 편이 빠르다. 동의항목은 `추가기능신청 / 개인정보 / 접근권한 / 대표채널`
네 섹션으로 나뉘고 이메일·닉네임은 **개인정보** 아래에 있다.

## 안드로이드 플랫폼 등록 없이도 카카오톡 로그인이 됐다

패키지명·키 해시를 콘솔에 등록하지 않은 상태에서도 `loginWithKakaoTalk()` 가
성공했다(`[auth] 카카오톡으로 로그인 성공`). 등록은 해 두는 편이 맞지만, 로그인이
안 될 때 **가장 먼저 의심할 대상은 아니다.**

**How to apply:** 카카오 로그인이 실패하면 순서대로 — (1) 활성화 ON인지,
(2) 앱이 요구하는 사용자 정보가 개인 앱에서 받을 수 있는 항목인지,
(3) 그다음에 앱키·키 해시·플랫폼 등록. 서버 쪽 실패 원인은
`docker logs pmhllll12-all-auth-1` 의 HTTP 상태코드가 가장 빠르다.
